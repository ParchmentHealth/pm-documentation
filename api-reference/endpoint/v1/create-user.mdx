## Overview

Creates a Parchment login for a user in your organization and assigns roles. When `access_roles` contains `provider` or `rx_queue_manager`, Parchment also verifies the HPI-I against the HI Service and creates a provider record.

A `201` is not always a complete success. Read `code`. Every `USER_CREATED_PROVIDER_*` code means the login and roles exist but there is **no provider record**, and the user **cannot create prescriptions**.

The response returns `user_id` only. There is no `partner_user_id`. Map `user_id` to your own record.

## Request Example

```json
{
  "given_name": "Darlene",
  "family_name": "Cameron",
  "date_of_birth": "1969-10-02",
  "sex": "F",
  "email": "darlene.cameron@example.com",
  "phone": "0412345678",
  "access_roles": ["admin", "provider"],
  "hpii_number": "8003614900029560",
  "prescriber_type": "M",
  "prescriber_number": "1234567",
  "qualifications": "MBBS, FRACGP",
  "title": "Dr",
  "provider_number": "123456789",
  "ahpra_number": "MED0000932846",
  "hospital_provider_number": "H123456"
}
```

## Result Codes

| `code` | Provider record | Cause | Action |
|---|---|---|---|
| `USER_CREATED` | Yes | All steps completed. | None. |
| `USER_CREATED_PROVIDER_NOT_FOUND` | **No** | The HI Service found no HPI-I record for the supplied demographics. | Correct the demographics. Call Update User with `provider_details`. |
| `USER_CREATED_PROVIDER_SEARCH_FAILED` | **No** | The lookup could not run: no HPI-O, HI Service down, or data rejected. | Check the organization has an HPI-O. Retry later. |
| `USER_CREATED_PROVIDER_ALREADY_EXISTS` | **No** | Another active provider in this organization holds this `hpii_number`. | Disable the duplicate, or call Update User with the correct HPI-I. |
| `USER_CREATED_PROVIDER_INVALID_PARAMS` | **No** | The provider record was rejected. | Contact Parchment support with the `requestId`. |
| `USER_CREATED_PROVIDER_RESOURCE_NOT_FOUND` | **No** | A required record (usually the organization) was not found. | Contact Parchment support with the `requestId`. |
| `USER_CREATED_PROVIDER_FAILED` | **No** | Provider creation failed for another reason. | Contact Parchment support with the `requestId`. |
| `USER_CREATED_ROLES_FAILED` | **No** | The login exists but no roles were assigned. | Contact Parchment support with the `requestId`. |

<Warning>
  A user with `rx_queue_manager` but not `provider` always returns `USER_CREATED`, even when the provider record was not created. Read the user back and check `provider_details` is not `null`.
</Warning>

## Response Fields

| Field | Type | Description |
|---|---|---|
| `user_id` | string | Parchment's identifier for the new user. The only identifier returned. |
| `warning` | string | Partial success only. Names the step that did not complete. Branch on `code`, not on this text. |

## Request Fields

| Field | Required | Rule |
|---|---|---|
| `given_name` | Always | Not empty. Legal given name only, no middle names. |
| `family_name` | Always | Not empty. |
| `email` | Always | Valid email. Unique across all of Parchment, stored lower-case. |
| `access_roles` | No | `admin`, `provider`, `receptionist`, `rx_reader`, `rx_queue_manager`. Omitted: the user gets `member` only. |
| `date_of_birth` | `provider` or `rx_queue_manager` | `YYYY-MM-DD`. |
| `sex` | `provider` or `rx_queue_manager` | `M`, `F`, `I`, `N`. |
| `hpii_number` | `provider` or `rx_queue_manager` | 16 digits. Must pass the HPI-I check digit. |
| `qualifications` | `provider` or `rx_queue_manager` | Not empty. |
| `prescriber_type` | `provider` | `M` medical, `E` optometrist, `U` nurse, `F` midwife, `D` dentist, `V` veterinarian, `T` podiatrist, `C` pharmacist. |
| `prescriber_number` | `provider`, unless `prescriber_type` is `T` | Max 10 characters. |
| `provider_number` | No | Max 10 characters. |
| `ahpra_number` | No | 3-letter prefix + 10 digits, e.g. `MED0000932846`. |
| `erx_entity_id` | No | Exactly 5 alphanumeric characters. |
| `title`, `phone`, `hospital_provider_number` | No | Free text. `phone` is not validated. Send an Australian number such as `0412345678` or `+61412345678`. |

## Status Codes

| Code | Meaning |
|---|---|
| 201 | User created. Read `code`. |
| 400 | The identity provider rejected the user parameters, for example a malformed email. |
| 401 | Authentication failed, or the token lacks the `create:user` scope. |
| 403 | Rejected by the API gateway, or the user creation service refused access. |
| 404 | Platform configuration error. Contact Parchment support with the `requestId`. |
| 409 | A Parchment user already exists with this email, possibly in another organization. |
| 422 | Validation failed. See `error.validation`. |
| 429 | Rate limited by the identity provider. Retry with back-off. |
| 500 | Unexpected error, including a request body that is not valid JSON. |

## Notes

- The HI Service lookup sends `hpii_number`, `given_name`, `family_name`, `date_of_birth` and `sex`. All five must match the record held by Services Australia.
- Parchment never returns the HI Service reason or the HPI-I number. Quote the `requestId` to Parchment support.
- Patient operations are not affected by a missing provider record. Patients belong to the organization.
