## Response Fields

### Success Response Data

| Field       | Type   | Description                                                                             |
| ----------- | ------ | --------------------------------------------------------------------------------------- |
| `user_id`   | string | Parchment's unique identifier for the new user. Store it — it is the only handle you get. |
| `warning`   | string | Present only on a partial success. Tells you which follow-up step did not complete.       |

<Warning>
  The request body has no `partner_user_id` field for this endpoint. Any value you send is ignored, and no such identifier is returned.
</Warning>

### Common Response Fields

All responses include these standard fields:

| Field        | Type    | Description                             |
| ------------ | ------- | --------------------------------------- |
| `success`    | boolean | Indicates if the request was successful |
| `statusCode` | number  | HTTP status code                        |
| `timestamp`  | string  | ISO 8601 timestamp of the response      |
| `requestId`  | string  | Unique identifier for debugging         |

## Status Codes

| Code  | Status                | Description                                                                                  |
| ----- | --------------------- | -------------------------------------------------------------------------------------------- |
| `201` | Created               | User created. Check `code` — the user may be created with a warning (see Result Codes below). |
| `400` | Bad Request           | The identity provider rejected the user parameters (for example, a malformed email)          |
| `401` | Unauthorized          | Authentication required, token invalid, or the token lacks the `create:user` scope           |
| `403` | Forbidden             | Rejected by the API gateway                                                                  |
| `404` | Not Found             | Platform configuration error. Contact Parchment support with the `requestId`.                |
| `409` | Conflict              | A Parchment user already exists with this email address                                      |
| `422` | Unprocessable Entity  | Request validation failed — see `error.validation` for the field-level detail                |
| `429` | Too Many Requests     | Rate limited by the identity provider. Retry with back-off.                                  |
| `500` | Internal Server Error | Unexpected server error, including a request body that is not valid JSON                     |

<Note>
  Email addresses are unique across the whole Parchment platform, not per organization. A `409` means the address is already registered to a Parchment user — possibly in a different organization. Use a different address, or contact Parchment support to move the existing user.
</Note>

## Result Codes

A `201` response is not always a complete success. Always read the `code` field.

| `code`                                  | Provider record created? | What it means                                                                                     | What to do                                                                                                 |
| --------------------------------------- | ------------------------ | ------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `USER_CREATED`                          | Yes                      | The user, the roles and (for provider roles) the provider record were all created.                  | Nothing. The user can prescribe.                                                                           |
| `USER_CREATED_PROVIDER_NOT_FOUND`       | **No**                   | The HI Service could not match the HPI-I to the supplied demographics.                              | Correct the demographics and call Update User with the corrected `provider_details`.                        |
| `USER_CREATED_PROVIDER_SEARCH_FAILED`   | **No**                   | The HI Service lookup could not run — the organization has no HPI-O, the HI Service was unavailable, or the search data was rejected. | Check the organization has an HPI-O. Retry later. If it continues, contact Parchment support with the `requestId`. |
| `USER_CREATED_PROVIDER_ALREADY_EXISTS`  | **No**                   | The `hpii_number` is already held by another **active** provider in the same organization.          | Check for a duplicate account for this prescriber. Disable the old user, or call Update User with the correct HPI-I. |
| `USER_CREATED_PROVIDER_INVALID_PARAMS`  | **No**                   | The provider record was rejected as invalid.                                                        | Check the provider fields, then contact Parchment support with the `requestId`.                            |
| `USER_CREATED_PROVIDER_RESOURCE_NOT_FOUND` | **No**                | A record needed to build the provider (usually the organization) was not found.                     | Contact Parchment support with the `requestId`.                                                            |
| `USER_CREATED_PROVIDER_FAILED`          | **No**                   | Provider creation failed for another reason.                                                        | Contact Parchment support with the `requestId`.                                                            |
| `USER_CREATED_ROLES_FAILED`             | **No**                   | The user was created but no roles were assigned.                                                    | Contact Parchment support with the `requestId`.                                                            |

<Note>
  To repair any of these, call Update User with the corrected `provider_details`, then read the user back and check `provider_details` is not `null`. See the Update User page, section "HPI-I updates and partial user creation".
</Note>

<Warning>
  **Treat every `USER_CREATED_PROVIDER_*` code as a failure to onboard a prescriber.** The login account exists and the roles are assigned, but there is no provider record. That user **cannot create prescriptions** until the provider record exists.

  Patient operations are not affected. Patients belong to the organization, not to the provider, so you can still create, read and update patients for that organization.
</Warning>

### How the provider record is built

When `access_roles` contains `provider` or `rx_queue_manager`, Parchment does two extra steps after it creates the user:

1. **HI Service lookup.** Parchment sends `hpii_number`, `family_name`, `given_name`, `date_of_birth` and `sex` to the Healthcare Identifiers Service. **All five values must match the HPI-I record held by Services Australia.** A mismatch in any one of them returns `USER_CREATED_PROVIDER_NOT_FOUND`. The most common causes are a middle name sent in `given_name`, a maiden or married family name, and a wrong date of birth.
2. **Provider creation.** Parchment writes the provider record with the HPI-I status returned in step 1. If the same `hpii_number` is already held by another active provider in that organization, the request returns `USER_CREATED_PROVIDER_ALREADY_EXISTS`.

Parchment never returns the reason from the HI Service, and never returns the HPI-I number itself. Quote the `requestId` when you ask Parchment support to check a specific lookup.

### Phone Number Format

<Note>
  The API does not currently validate `phone`. Any string is accepted and stored. Send an Australian number in one of the formats below so the number prints correctly on prescriptions.
</Note>

**✅ Recommended formats:**

- `0412345678` - Mobile number (domestic format)
- `0312345678` - Melbourne landline (domestic format)
- `0212345678` - Sydney landline (domestic format)
- `0712345678` - Brisbane landline (domestic format)
- `0812345678` - Adelaide landline (domestic format)
- `61412345678` - International mobile (without + prefix)
- `+61312345678` - International landline (with + prefix)

**❌ Avoid:**

- `0123456789` - Starts with 1 (invalid area code)
- `04123456789` - Too many digits
- `041234567` - Too few digits
- `04-1234-5678` - Contains formatting characters
- `+1234567890` - Non-Australian number

### String Length Requirements

- **Family Name**: 1-255 characters, cannot be empty
- **Given Name**: 1-255 characters, cannot be empty
- **HPII Number**: 16 digits exactly
- **Prescriber Number**: 1-10 characters
- **AHPRA Number**: 13 characters exactly — a 3-letter profession prefix and 10 digits, for example `MED0000932846`
- **Provider Number**: 1-10 characters
- **eRx Entity ID**: 5 alphanumeric characters exactly
- **Qualifications**: 1-255 characters


### Sex

- `M` (Male)
- `F` (Female)
- `I` (Indeterminate)
- `N` (Not-stated)

### Access Roles

Valid values for `access_roles` array:

- `admin` (Administrative access)
- `provider` (Healthcare provider access)
- `receptionist` (Can read patient demographics)
- `rx_reader` (Can reissue scripts)
- `rx_queue_manager` (Can manage the prescription queue on behalf of prescribers)

When the `provider` or `rx_queue_manager` role is included, additional fields become required:

- `provider`: `date_of_birth`, `sex`, `hpii_number`, `qualifications`, and `prescriber_type` (plus `prescriber_number` unless `prescriber_type` is "T")
- `rx_queue_manager`: `date_of_birth`, `sex`, `hpii_number`, and `qualifications` (`prescriber_type` and `prescriber_number` are **not** required)

### Prescriber Types

Valid values for `prescriber_type` when role is "provider":



- `M` (Medical Practitioner)
- `E` (Eye/Optometrist)
- `U` (Nurse) 
- `F` (Midwife)
- `D` (Dentist)
- `V` (Vetinarian)
- `T` (Podiatrist)
- `C` (Pharmacist)

## Integration Notes

1. **Store the Request ID**: Always log the `requestId`. Parchment support needs it to trace a specific call.
2. **Store the user_id**: `data.user_id` is the only identifier returned. Map it to your own user record.
3. **Always read the `code` field**: A `201` does not guarantee a working prescriber. See Result Codes above.
4. **Validation Errors**: Use the `error.validation` array to show field-level messages to your user.
5. **Email is globally unique**: A `409` means the email is already registered somewhere on the Parchment platform, not only in your organization.
6. **Provider Role Requirements**: When you create a user with the `provider` or `rx_queue_manager` role, send all required identity fields (see Access Roles above). These roles create a provider record that Parchment verifies against the HI Service.
7. **Match the HI Service exactly**: Send the prescriber's legal given name and family name, as registered with AHPRA and Services Australia. Do not add middle names to `given_name`.
8. **Phone Format**: The API does not validate `phone`. Send an Australian number in a recommended format. See Phone Number Format above.
