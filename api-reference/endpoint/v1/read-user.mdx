## Checking a prescriber can prescribe

Read `is_escript_ready.can_prescribe`. It is true only when the user can create an electronic prescription now.

When it is false, the other flags say why:

| Flag | False means |
| --- | --- |
| `hpii_verified` | HPI-I not confirmed by the HI Service. Send the correct identity to Update User. |
| `erx_registered` | No eRx entity ID yet. Parchment issues it once the profile is verified. |
| `mims_ready` | Medication catalogue still provisioning. Automatic. |
| `account_enabled` | Account is disabled. Re-enable it. |
| `profile_complete` | Prescriber profile incomplete. Advisory only; does not block `can_prescribe`. |

`is_escript_ready` is absent for users without the `provider` or `rx_queue_manager` role.

<Note>
  There is no `external_user_id` or `partner_user_id`. Map `user_id` to your own record.
</Note>

## Response Fields

### Success Response Data

| Field              | Type     | Description                                     |
| ------------------ | -------- | ----------------------------------------------- |
| `user_id`          | string   | Parchment's unique user identifier              |
| `email`            | string   | User's email address                            |
| `full_name`        | string   | User's full display name                        |
| `access_roles`     | array    | Array of user roles (admin, provider, etc.)    |
| `details`          | object   | Core user demographics (always present — see below) |
| `provider_details` | object \| null | Provider fields. Present only for `provider` / `rx_queue_manager` roles. `null` means the role is held but no provider record exists |
| `is_escript_ready` | object | Readiness booleans. Present only for `provider` / `rx_queue_manager` roles |

### Details Object

| Field           | Type             | Description                                            |
| --------------- | ---------------- | ------------------------------------------------------ |
| `given_name`    | string \| null   | Provider record first, else split from `full_name`     |
| `family_name`   | string \| null   | Provider record first, else split from `full_name`     |
| `title`         | string \| null   | Professional title                                     |
| `date_of_birth` | string \| null   | `null` when no provider record exists                  |
| `sex`           | string \| null   | `null` when no provider record exists                  |

Every key is always present. An unknown value is `null`, never omitted.

### Provider Details Object

Every key is always present; an unset value is `null`.

| Field                      | Type   | Description                                    |
| -------------------------- | ------ | ---------------------------------------------- |
| `hpii_number`              | string | Healthcare Provider Individual Identifier     |
| `prescriber_number`        | string | Prescriber number                              |
| `prescriber_type`          | string | Prescriber type (M/N/D/P/T)                   |
| `ahpra_number`             | string | AHPRA registration number                     |
| `qualifications`           | string | Professional qualifications                   |
| `hospital_provider_number` | string | Hospital provider number                       |
| `family_name`              | string | Provider's family name                         |
| `given_name`               | string | Provider's given name                          |
| `date_of_birth`            | string | Date of birth (YYYY-MM-DD format)             |
| `sex`                      | string | Sex (M/F/I/O)                                  |
| `phone`                    | string | Australian phone number                        |
| `australian_address`       | object | Provider's Australian address                  |

### Australian Address Object

| Field           | Type   | Description                 |
| --------------- | ------ | --------------------------- |
| `street_number` | string | Street number               |
| `street_name`   | string | Street name                 |
| `suburb`        | string | Suburb                      |
| `state`         | string | Australian state            |
| `postcode`      | string | Australian postcode         |

### is_escript_ready Object

| Field              | Type    | Description                                            |
| ------------------ | ------- | ------------------------------------------------------ |
| `can_prescribe`    | boolean | User can create an electronic prescription now          |
| `hpii_verified`    | boolean | HPI-I confirmed against the HI Service                  |
| `profile_complete` | boolean | Prescriber profile complete. Advisory                   |
| `erx_registered`   | boolean | eRx entity ID issued                                    |
| `mims_ready`    | boolean | Medication catalogue provisioned                        |
| `account_enabled`  | boolean | Account is not disabled                                 |

## Path Parameters

| Parameter         | Type   | Required | Description              |
| ----------------- | ------ | -------- | ------------------------ |
| `organization_id` | string | Yes      | Organization identifier  |
| `user_id`         | string | Yes      | User identifier          |

## Status Codes

| Code  | Status                | Description                                      |
| ----- | --------------------- | ------------------------------------------------ |
| `200` | OK                    | User details retrieved successfully              |
| `400` | Bad Request           | Invalid request format or missing parameters     |
| `401` | Unauthorized          | Authentication required or token invalid or scope invalid        |
| `404` | Not Found             | User not found                                   |
| `500` | Internal Server Error | Unexpected server error                          |



## Integration Notes

1. `provider_details` reflects the user's role, not their capability. Use `is_escript_ready.can_prescribe` for that.
2. Requires the `READ_USER` scope.
3. Log `requestId` for support requests.
